# 프론트엔드 디자인 방향과 결정 기록 (2026-11-17)

브랜치 `feat/frontend-redesign`에서 진행하는 화면 리팩토링의 근거 문서다. **코드를 바꾸기 전에** 정했다.
- 디자인 방향은 `frontend-design` 스킬(anthropics/skills)의 절차를 따랐다. 주제를 정하고, 색·글꼴·레이아웃 계획을 세운 뒤, "어느 프로젝트에나 나올 기본값이 아닌지" 다시 검토했다.
- 레퍼런스 사이트는 Chrome에서 열어 `getComputedStyle`로 실제 값을 뽑았다. 토큰 추출 도구(extract-design-system)는 쓰지 않았다. 검토하지 않은 서드파티 패키지(dembrandt)를 실행해야 하는 데 비해 얻는 것이 적어서다.
- 성능과 접근성 측정 조건, 수치: [frontend-lighthouse.md](frontend-lighthouse.md)

**범위**: 화면 표현만 바꾼다(레이아웃, 색, 글꼴, 컴포넌트 모양, 접근성 마크업). 아래 로직은 건드리지 않는다.
- 채팅 문의: 상세 버튼에서 방 생성 API 1회 호출 후 roomId로 이동, 호출 중 버튼 비활성화, 채팅 페이지 `isCreatingChatRoom`
- STOMP: `connectHeaders` Authorization, `/sub/chat/room/{roomId}` 구독, `/pub/chat/message` 발행, payload에 senderId 없음, `reconnectDelay: 5000`, `pendingSubscribeRoomIdRef`, 한글 IME `isComposing`
- 보호 페이지는 `isHydrated` 이후에만 `/login` 리다이렉트 판단
- 찜하기 낙관적 업데이트와 롤백(상세, 마이페이지)
- `KakaoMapPicker`의 `hasUserPickedRef`, 카카오맵 SDK 로더 Promise 캐싱
- 멀티파트 요청에서 Content-Type 직접 지정 금지
- `/chat`, `/oauth/callback`의 `<Suspense>`
- Vitest 14케이스(`useCurrentUserId` 10, `productApi` 4) 전후 통과

## 1. 레퍼런스 분석 (유닉스 공식몰)

- 홈 https://unixshop.co.kr/ 과 상품 목록 https://unixshop.co.kr/product/list.html?cate_no=111 을 참고했다.
- 실제 브랜드 쇼핑몰이므로 로고, 브랜드명, 상품 사진, 문구, 브랜드 고유색은 가져오지 않았다. 분석 캡처는 저장소에 넣지 않았다.
- 데스크톱은 PC 사이트(1000px 고정 폭)에서, 모바일은 모바일 전용 사이트(`m.unixshop.co.kr`)를 375px로 띄워서 쟀다.

### 1-1. 같은 항목으로 잰 비교 (Campus는 리팩토링 전)
대표 요소: 유닉스 카드 `li#anchorBoxId_538`(`ul.prdList`), 탭 `li.xans-product-displaycategory`, 개수 `p.prdCount` / Campus 카드 `ProductCard`의 `div.rounded-card.border`, 칩 `main button.rounded-full`

| 항목 | 유닉스 목록 | Campus 메인(전) |
|---|---|---|
| 본문 최대 폭 | 1000px | 1152px |
| 열 수 (데스크톱 / 375px) | 4 / 2 | 4 / 2 |
| 카드 사이 가로 / 세로 간격 | 12px / 40px | 24px / 24px |
| 카드 안 여백 | 글자 좌우 8px, 사진과 제목 사이 20px | 16px / 16px / 8px |
| 테두리 / 그림자 / radius | 없음 / 없음 / 0 | 1px / 있음 / 20px |
| 이미지 비율, 카드 높이에서 차지하는 비율 | 1:1, 74% | 1:1, 65% |
| 카드 안 정보 줄 수 | 2줄(모바일 4줄) | 4줄 |
| 글자색 수(카드 안) | 6(3) | 7 |
| 글자 크기 단계 / 굵기 | 5단계 / 3가지 | 5단계 / 4가지 |
| 필터 | 1px 밑줄 탭 + 체크박스 패널 | 알약 칩 두 줄 |

### 1-2. 깔끔해 보이는 이유 (숫자로)
1. 상자가 없다. 테두리 0, 그림자 0, radius 0. 카드는 사진과 글자 두 줄뿐이다.
2. 세로 간격(40px)이 가로 간격(12px)보다 3배 넘게 커서, 상자 없이도 "사진 + 설명"이 한 묶음으로 읽힌다.
3. 카드 높이의 74%가 사진이다.
4. 카드 안 색은 3개이고, 강조색(파랑)은 할인율 하나에만 쓴다.
5. 선은 1px 회색 밑줄로만, 탭과 영역 구분에만 쓴다.

### 1-3. 레퍼런스에서 버린 것
- 제목과 가격을 한 줄에 두는 배치: 상품명이 "에어…"로 잘린다(제목 칸 51px)
- 회색 글자 `#8b8b8b` 3.41:1, 할인 파랑 2.73:1, 10px 글자: 대비와 크기 미달
- radius 0: 사용자가 찍은 사진은 품질이 제각각이라 각진 모서리가 거칠어 보인다
- 반응형 대신 모바일 사이트를 따로 두는 구조, 배너 등장 애니메이션

### 1-4. 리팩토링 전 Campus의 문제
- 대비 미달: 옅은 글자 `#a89c8b` 2.35~2.69, 코랄 버튼 흰 글자 2.82, 입력창 경계 1.14 등([frontend-lighthouse.md](frontend-lighthouse.md) 2절)
- 375px에서 헤더가 두 줄로 꺾이고 문서 폭이 397px로 가로 스크롤이 생긴다
- frontend-design 스킬이 "AI 생성 디자인의 흔한 기본값"으로 꼽는 두 가지와 겹친다: 크림 바탕 + 코랄 강조색, 둥근 카드 + 테두리 + 옅은 그림자 + hover 떠오름

## 2. 디자인 방향 (2026-11-17 사용자 승인)

### 2-1. 한 줄 콘셉트
**"물건 사진에 가격표 한 장"**
- 카드는 상자 없이 사진과 그 아래 가격표(제목, 가격, 거래 정보)로만 만든다.
- 사진 위에 붙는 표식은 판매 상태 하나뿐이다.
  - 기본값인 판매중은 표시하지 않는다. 예약중과 판매완료만 사진 왼쪽 위에 글자 태그로 붙인다.
  - 판매완료는 사진을 흑백으로 흐리게 하고 "판매완료" 글자 태그도 함께 둔다. 색만으로 구분하지 않기 위해서다.
  - 붙은 태그는 예외 상황만 알리므로 목록이 조용해진다.

### 2-2. 색 토큰 (이름은 그대로, 값만 바꿈)
| 토큰 | 전 | 후 | 대비 |
|---|---|---|---|
| `bg` | `#fbf8f4` | `#FFFFFF` | |
| `surface-alt` | `#f5efe5` | `#F3F4F5` | |
| `text` | `#241c15` | `#17191C` | 17.61 |
| `text-muted` | `#7a6f62` | `#4E5560` | 7.52 |
| `text-faint` | `#a89c8b` | `#6B7280` | 4.83 |
| `border` | `#e8e0d3` | `#E3E5E8`(장식용 구분선 전용) | |
| `border-strong` | `#d9cebc` | `#8A9099`(입력창 경계) | 3.22 |
| `accent` | `#ff6b45` | `#17694A`(주요 버튼, 선택된 탭에만) | 흰 글자 6.65 |
| 예약중 태그 | 연한 노랑 배지 | 흰 글자 / `#9A5B00` | 5.43 |
| 판매완료 태그 | `#a89c8b` / `#f5efe5` 2.36 | 흰 글자 / `#4E5560` | 7.52 |

- `text-faint`는 `surface-alt` 위에서 4.39로 기준에 못 미친다. 그래서 회색 배경 위 글자(예: "이미지 없음")에는 `text-muted`를 쓴다.

### 2-3. 글꼴과 크기
- 글꼴: OS 한글 글꼴 스택. 처음에는 Pretendard를 유지하려 했지만, 측정해 보니 그 글꼴(2MB 전체 가변 글꼴)이 모바일 LCP 12~13초의 원인이었다. dynamic-subset과 비교한 과정은 [frontend-lighthouse.md](frontend-lighthouse.md) 3절.
- 굵기는 400, 600, 700만 쓴다(800 제거).
- 크기는 13, 14, 16, 20, 24px 다섯 단계. 가장 작은 글자는 13px.

### 2-4. radius와 그림자
- 사진 8px, 입력창과 버튼 8px, 모달 12px
- 카드 그림자는 없앤다. 그림자는 모달과 드롭다운처럼 떠 있는 요소에만 남긴다.

### 2-5. 상품 카드 (정보 4줄 → 3줄)
```
┌──────────────┐
│[예약중]      │ ← 예약중·판매완료일 때만. 판매완료는 흑백 + 글자 태그
│    사진 1:1  │
└──────────────┘
아이패드 에어 5세대 64GB      ← 16/600, 한 줄 말줄임(가격과 같은 줄에 두지 않음)
430,000원                     ← 16/700, "원" 표기
중앙도서관 앞   3시간 전   ♡ 1 ← 13px. 거래 장소는 짧은 이름 한 줄, 넘치면 말줄임
```
- 판매자 이름과 조회수는 목록 카드에서 빼고 상세에서만 보여 준다.
- 카드 hover 떠오름은 없앤다. 대신 누를 수 있다는 피드백으로 사진을 살짝 어둡게 하고 제목에 밑줄을 넣는다. 키보드 `focus-visible` 표시도 넣는다. 움직임은 `prefers-reduced-motion`을 따른다.

### 2-6. 메인 배치
- 제목 → 검색창 → 카테고리 1px 밑줄 탭
- 다음 줄: 왼쪽 결과 개수, 오른쪽 상태 필터 3개(작은 텍스트 토글). 칩 두 줄이 한 줄로 준다.

### 2-7. 구현하면서 정한 것
승인한 방향(2-1~2-6)을 화면에 옮기면서 따로 정한 세부 사항이다.

| 항목 | 결정 | 이유 |
|---|---|---|
| 좁은 화면 헤더 | 채팅·마이페이지·로그아웃을 아이콘 버튼(접근 가능한 이름 포함)으로, "상품 등록"만 글자 버튼 | 375px에서 로고와 함께 한 줄에 들어가는 최대치. 가장 자주 쓰는 동작만 글자로 남겼다 |
| 입력창 | 회색 바탕 → 흰 바탕 + `border-strong` 경계, 글자 16px | 경계 대비 3:1을 맞추려면 경계선이 보여야 한다. 16px 미만이면 iOS Safari가 포커스 때 화면을 확대한다 |
| 채팅 말풍선 | 내 메시지 연한 초록(`accent-soft`/`accent-ink` 8.82:1), 상대 회색 | 진한 강조색은 주요 버튼과 선택된 탭에만 쓴다는 원칙(2-2). 말풍선 전체를 진한 초록으로 칠하면 대화가 버튼처럼 보인다 |
| 채팅방 목록 선택 상태 | 강조색 배경 → 회색 배경 | 위와 같은 이유 |
| 카드 사진 hover | 사진 위에 6% 어두운 막 + 제목 밑줄, 크기 변화 없음 | 움직임 없이 누를 수 있다는 신호만 준다(2-5) |
| 첫 줄 사진 | 앞 4장 지연 로딩 해제, 앞 2장 `fetchPriority="high"` | LCP 요소가 첫 카드 사진이라서. 다만 측정상 효과는 없었다([frontend-lighthouse.md](frontend-lighthouse.md) 4-2) |
| 굵기 | 본문 400(기본값), 강조 600, 제목·가격 700 | 500을 쓰던 곳은 600으로, 선택 안 된 탭과 헤더 메뉴는 400으로 둬서 선택 상태와 굵기 차이를 남겼다 |
| 카카오 로그인 버튼 | 노란 바탕(`#FEE500`) 그대로 | 카카오 디자인 가이드 색이라 토큰에 맞추지 않는다 |

## 3. "화면만 변경" 범위의 예외: 목록 API에 필드 2개 추가

### 무엇을 바꿨나
- 백엔드 `ProductListResponse`에 `tradeLocationName`(거래 장소), `createdAt`(등록 시각)을 추가했다. 두 값은 엔티티(`Product`, `BaseTimeEntity`)에 이미 있었고, 응답에만 빠져 있었다.
- 목록 캐시 이름을 `products` → `products-v2`로 바꿨다(`ProductCacheService`).

### 왜 예외로 했나
- 브리프에서 중고거래 카드에는 판매 상태, 찜 수, **거래 장소, 등록 시간**이 들어가야 한다고 했다. 그런데 목록 응답에는 찜 수만 있었다. 화면만으로는 이 정보를 보여 줄 수 없었다.
- 바꾸는 범위가 작다. 응답 필드 2개를 추가하는 것뿐이고, 기존 필드와 동작은 바뀌지 않는다. 같은 DTO를 쓰는 마이페이지 목록(`/api/products/me`, `/me/likes`)에도 같은 두 필드가 생긴다.

### 캐시를 어떻게 처리했나
- `/api/products/search`는 Elasticsearch를 쓰지 않는다. MySQL(QueryDSL) 결과를 Redis에 캐시한다(첫 페이지만, TTL 10분, `@class`가 붙은 JSON).
- 필드만 추가하면 배포 직후 최대 10분 동안 예전 캐시를 읽게 된다. 그 경우 오류는 나지 않지만 두 필드가 `null`로 와서 카드에 장소와 시간이 빠진다.
- 캐시 이름에 버전을 붙여(`products-v2`) 예전 키를 아예 읽지 않게 했다. 예전 키는 TTL 10분 뒤 저절로 사라진다. 배포할 때 Redis를 비우는 단계를 따로 기억하지 않아도 된다.
- 검증: `ProductServiceTest.검색_목록에_거래장소와_등록시각이_포함되고_캐시에서_읽어도_유지된다`
  - 첫 조회로 캐시를 채운 뒤 DB 행을 지우고 다시 조회한다. 두 번째 결과는 Redis에서만 올 수 있다.
  - 그 결과의 `tradeLocationName`과 `createdAt`이 첫 조회와 같은지 확인한다.
  - 필드를 추가하기 전에는 이 테스트가 컴파일 단계에서 실패했다.
- 백엔드 테스트 전체 통과: 12개 클래스, 39개, 실패 0 (2026-11-17)
- 응답 형식: `"createdAt": "2026-11-17T10:29:05.698204"`. 서버 시간대(Asia/Seoul) 기준이고 시간대 표기가 없다. 프론트는 이 값을 "3시간 전" 같은 상대 시간으로만 보여 준다.

## 4. 화면 리팩토링에서 바뀐 동작

화면만 바꾸는 것이 원칙이지만, 배치를 바꾸면서 사용자가 겪는 동작이 달라진 부분이다.

| 항목 | 전 | 후 | 이유 |
|---|---|---|---|
| 메인 "필터 초기화" 버튼의 위치와 모양 | 검색어·카테고리·상태 중 하나라도 걸려 있으면 상태 칩 줄 오른쪽에 아이콘 + "필터 초기화" 표시 | 표시 조건은 같다(하나라도 걸려 있으면 표시). 위치는 결과 개수("N개 상품") 옆, 모양은 작은 밑줄 글자 버튼 "초기화". 결과가 0개일 때는 빈 상태 안에도 "필터 초기화" 버튼을 하나 더 둔다 | 필터를 한 줄(결과 개수 + 상태 토글)로 줄이면서 칩 줄이 없어졌다. 초기화는 결과 개수를 바꾸는 동작이라 개수 옆에 두었다. 결과가 0개로 막혔을 때는 눈에 잘 띄는 버튼이 필요해 빈 상태 안에도 남겼다 |

- 두 버튼 모두 기존 `handleReset`(검색어·카테고리·상태를 비우고 다시 검색)을 그대로 호출한다. 바뀐 것은 위치와 모양이다.
- 글자 버튼에는 스크린 리더용 이름 "검색어와 필터 초기화"를 붙였다(화면 글자는 "초기화").
- 검색어만 지우고 카테고리·상태는 유지하는 수단은 전에도 지금도 없다. 검색창 지우기 버튼은 5절에서 별도로 검토한다.

## 5. 별도 작업 목록 (이번 브랜치에서 하지 않음)

동작이 바뀌거나 범위를 넘는 항목이다.

| 항목 | 위치 | 이유 |
|---|---|---|
| **완료** — 상품 등록·수정·상태 변경 때 목록 캐시 비우기(`@CacheEvict`) | `ProductService`, `ProductCacheService` | (완료 전 기록) 지금은 비우는 코드가 없어서 목록에 최대 10분 늦게 반영된다. 동작이 바뀌는 변경이다. → 등록·수정·삭제·상태 변경·거래완료 때 커밋 직후 비우도록 수정함 |
| `pretendard` 의존성 제거 | `frontend/package.json` | 글꼴을 OS 스택으로 바꾼 뒤 쓰이지 않는다. 의존성 변경은 이번 범위 밖 |
| lint 에러 4개(`set-state-in-effect`) | `app/page.tsx`, `app/products/[id]/edit/page.tsx`, `src/context/AuthContext.tsx`, `src/hooks/useUser.ts` | 리팩토링 전부터 있었다(main에서도 같은 8개). 그중 `AuthContext`의 `isHydrated` 처리와 `useUser`는 건드리지 않기로 한 로직이다 |
| 검색창 지우기 버튼(검색어를 비우고 바로 다시 검색) | `app/page.tsx` | 검색어만 지우고 다른 필터는 유지한 채 다시 검색하는 수단이 없다("초기화"는 전부 비운다). 동작 추가라 범위 밖 |
| 첫 페이지 상품 데이터를 서버에서 받아 HTML에 넣기(서버 컴포넌트/SSR) | `app/page.tsx`, `app/products/[id]/page.tsx` | 모바일 LCP 3.0~3.5초는 이미지가 아니라 HTML → JS → API → 사진 체인이 정한다. 이미지 우선순위로는 줄지 않았다([frontend-lighthouse.md](frontend-lighthouse.md) 4-2). 데이터 흐름이 바뀌는 변경이라 범위 밖 |
| 카카오맵 타일 http 요청, `<area>` 역할 충돌 | 카카오맵 SDK | 외부 SDK 동작. Best Practices와 Accessibility 감점 원인 |
